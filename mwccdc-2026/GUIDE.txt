 THE THREE COMMANDS. THAT IS THE WHOLE SYSTEM.
--------------------------------------------------------------------------------
 On any Linux box, go to that box's folder and run, in this order:

     sudo bash harden.sh          1. lock it down   (asks before every change)
     sudo bash watch.sh           2. keep it alive  (watchdog + monitoring)
     sudo bash clean.sh           3. at the end     (evidence, then teardown)

 Add 'dry' to see the plan without changing anything:
     sudo bash harden.sh dry

 GETTING THE KIT ONTO A BOX
--------------------------------------------------------------------------------
     git clone https://github.com/<you>/<repo>.git mwccdc-2026
     cd mwccdc-2026

  The repo MUST be public. Internet Usage rule 4 forbids pulling from a private
  staging area during the competition.

  No network on the box? Serve it from your workstation instead:
     on the wkst:  python3 -m http.server 8000
     on the box:   curl -O http://<wkst-ip>:8000/mwccdc-2026.tgz && tar xzf mwccdc-2026.tgz

 THE FIVE RULES THAT CHANGE WHAT YOU DO
--------------------------------------------------------------------------------
 1. NO SOURCE-IP FILTERING on public services. Rule 9: it "may incur a penalty
    when detected", and allow-listing only the scoring engine is PROHIBITED.
    The kit refuses to do this. You may still block a specific attacking IP.
 2. NO SNAPSHOTS, NO SCRUBS, NO REVERTS. Rule 10. Every change is permanent.
    Back up first. The firewall's 5-minute auto-revert is your only undo.
 3. MAINTAIN ICMP everywhere. Rule 12. Ping is a scored service.
 4. PASSWORDS YES, USERNAMES NEVER. Rule 11.
 5. NO SYSTEM NAME OR IP CHANGES. Rules 6 and 7.

 Submit every password change at https://quotient.ccdc.events (PCR tab):
     username,password


 WHEN SOMETHING BREAKS
--------------------------------------------------------------------------------
  Locked out by the firewall   wait 5 min, it reverts itself
                               or: sudo bash ../firewall.sh undo
                               or from console: sudo sh /root/UNDO-FIREWALL.sh
  SSH broke after hardening    the kit auto-restores sshd_config if it fails its
                               test. From console:
                                 cp /etc/ssh/sshd_config.bak.<newest> /etc/ssh/sshd_config
                                 systemctl restart ssh
  Service will not start       systemctl status <name>
                               journalctl -u <name> -n 50
                               On Rocky: getenforce ; ausearch -m avc -ts recent
  Splunk up but 8000 down      sudo systemctl restart Splunkd ; wait 2 min
                               (known Splunk 10 cold-start race)
  Service keeps dying          that is someone killing it, not a crash:
                               sudo bash ../persistence.sh
  Lost the new passwords       shredded on purpose. Use the console and set them
                               again: sudo sh ../plan-b/2-pw.sh <user>
  Kit will not run at all      cat ../plan-b/PLAN-B.txt  (5 standalone sh scripts)


 WHERE THE SCORE COMES FROM
--------------------------------------------------------------------------------
  40%  service uptime     -> watch.sh is what protects this
  40%  injects            -> one person owns these FULL TIME from minute zero.
                             Responses must be an attached PDF. NISE runs on
                             Central time. Late = zero.
  20%  incident response  -> write findings down AS YOU GO:
                               echo "$(date '+%H:%M') <what, source IP>" >> /root/incidents.txt
                             clean.sh bundles it all at the end.

  Scoring runs every 2-4 minutes. An SLA hits after 5 failed checks, so you have
  roughly 10-20 minutes to notice and fix anything. The watchdog notices in 30s.
