 [ ] 0a. CONFIRMED ON THE PRACTICE VM (13 Nov): Splunk had NO systemd unit and no
         init script -- it was running, but nothing would restart it after a reboot,
         and red team CAN reboot your boxes. CHECK THIS ON THE REAL BOX FIRST:
             sudo bash splunk.sh check        look for "managed by:"
         If it says "managed by: NOTHING", fix it immediately:
             sudo bash splunk.sh fix          offers to enable boot-start
         or by hand -- NOTE Splunk refuses to do this while running, so stop first:
             ps -o user= -p $(pgrep -x splunkd | head -1)    # who does it run as?
             sudo /opt/splunk/bin/splunk stop
             sudo /opt/splunk/bin/splunk enable boot-start -systemd-managed 1 -user <thatuser>
             sudo systemctl daemon-reload
             sudo systemctl enable --now Splunkd
             systemctl is-active Splunkd                      # should say: active
         Then add it to the watchdog:  sudo bash splunk.sh watch
         THEN CHECK PORT 8000. Splunk 10 often comes up with the web tier down
         (8089/9997 fine, 8000 missing). One more 'systemctl restart Splunkd'
         fixes it. Confirmed on the practice box 13 Nov.
